# myzOS

[English](README.md) | **简体中文**

myzOS 是一个计划从零实现的小型操作系统内核，旨在通过实际开发理解操作系统的工作原理。项目面向 64 位 RISC-V，运行在 QEMU 的 `virt` 模拟计算机上，主要使用 Rust 开发，并配合少量 RISC-V 汇编。

项目希望把操作系统概念与具体实现联系起来：计算机如何进入内核、内存如何管理、程序如何运行，以及数据如何到达设备或文件。

> **项目状态：** myzOS 目前处于规划阶段。v0.1 定位为首个完整的教学版本，以下列出的能力均为计划范围，尚未实现。

## 项目概述

myzOS 将作为操作系统运行在 QEMU 模拟的计算机中。QEMU 提供虚拟的 CPU、内存和设备；myzOS 负责初始化和管理这些资源，向用户程序提供服务，并提供简单的命令行交互界面。

项目注重理解每个机制，并将实现规模控制在便于阅读、解释和调试的范围内。

## 技术架构

| 组成部分 | 设计选择 |
| --- | --- |
| CPU 架构 | 64 位 RISC-V，目标指令集为 RV64GC |
| 机器平台 | QEMU `virt` |
| 内核结构 | 按模块组织的单体内核 |
| 实现语言 | Rust，配合少量 RISC-V 汇编 |
| Rust 运行环境 | 使用 `no_std`，可使用 `core`，不依赖标准库 `std` |
| 执行模型 | v0.1 使用单个 hart，即一个 RISC-V 硬件线程 |
| 交互方式 | 串口控制台与简易 Shell |

内核将把体系结构相关代码、设备访问与内存管理、进程管理、文件服务分开组织。需要使用 `unsafe` 的底层操作将集中在小范围接口中，并记录其依赖的条件。

## v0.1 计划范围

v0.1 将贯通从机器启动到运行用户程序、访问文件的完整流程。

- [ ] **启动与控制台：** 进入内核，建立初始执行环境，通过串口提供交互输出和诊断信息。
- [ ] **内存管理：** 分配和回收物理内存页，建立 Sv39 页表，并管理内核与用户程序各自的地址空间。
- [ ] **异常与中断：** 处理异常、设备中断和定时器事件，为故障提供诊断信息。
- [ ] **用户程序与系统调用：** 在用户态执行程序，通过少量系统调用访问内核服务。
- [ ] **进程管理：** 在单个 hart 上支持基本的进程创建、调度、退出和资源回收。
- [ ] **块存储与文件系统：** 访问 QEMU 虚拟块设备，实现支持目录和基本文件创建、读取、写入的小型文件系统。
- [ ] **Shell：** 提供简单的命令行界面，用于启动用户程序和执行基础文件操作。

v0.1 的完成标准是：系统能够在 QEMU 中启动，进入用户态 Shell，运行简单程序，并通过内核服务创建、读取和写入文件。

## 设计原则

- **机制易于理解：** 优先采用明确的控制流程和清晰的数据结构，按实际需要进行优化。
- **边界清晰：** 明确硬件访问、内核服务与用户程序的职责，并记录它们之间的约定。
- **独立实现：** 借助已有系统学习概念和设计思路，在 myzOS 中自行实现，并能够解释实现原理。
